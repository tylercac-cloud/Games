# Audit 9 — reliability review, 2026-09-22

## Fixed

- **Locks were tied to labels, not data.** They now include fingerprints of every OHLC row for each member, plus row count and range. Changed prices under the same tag fail the match. A mismatch blocks the run; create another lock or explicitly deactivate it. The original lock stays in history.
- **A fast second click could reuse an active lock while saving.** Runs are serialized, relevant controls are disabled during the operation, and a matched lock is consumed before the first asynchronous save.
- **Daily refresh destroyed the old pool before it succeeded.** Downloads now stage separately and commit only after all three assets validate. Failure preserves the old pool, single dataset and active selection. Gaps and missing latest candles are displayed as warnings.
- **Unfinished candles entered fetched history.** Requests use completed UTC-aligned candles only, enforce their requested windows, deduplicate, sort and cap the returned count. Adjacent pages use an exclusive upper boundary to avoid losing one bar per page.
- **Network failures could hang indefinitely.** Each request, including JSON decoding, has a 15-second timeout; HTTP 429 stops after three attempts per page. Malformed/nonfinite prices, impossible OHLC and invalid request arguments are rejected.
- **The manual backup silently stopped updating with working storage.** It now updates in all storage modes after changes, import and clearing. It does not overwrite the box while you are editing it. Export distinguishes a download request from a failed/cancelled download.
- **Invalid inputs could corrupt the journal/history.** Zero/negative fills and sizes, negative/invalid fees, fractional history repairs, and null backup imports are rejected. Invalid imported budgets are skipped.
- Added individual pool-member removal and accurate release labeling. All prior archive, screener and Comal files are retained unchanged.

## Important remaining limits

- Locks are append-only **within this UI**, not immutable or cryptographically tamper-proof. Their lightweight fingerprints detect accidental edits; a person can still edit backups or local code. A lock does not prove that data was unseen. Active locks are session-only; saved historical locks survive reload/export/import.
- History repairs still need the correct dataset tag and honest counts. Existing dataset-tag accounting can miss overlapping history imported with a new date range or tag. This audit does not claim to reconstruct unknown historical trials or repair that statistical-accounting design.
- Browser storage is device-local; cloud persistence is still platform-dependent. Multiple tabs, externally edited backups and the existing cloud 1,000-record query limit require a separate persistence audit. Keep backups and use one active research tab.
- Existing trial/trade deduplication signatures omit some fields (including dataset/cost for trials). Backups with otherwise identical signed fields but different omitted fields can still collide. Retain originals; this pass does not certify a complete historical reconstruction.
- A download request cannot prove the browser saved a file. Verify the downloaded file yourself.
- The daily refresh covers BTC/ETH/SOL, not every Coinbase market. It does not generate a trade recommendation or execute orders. Live connectivity and current account-specific fees require verification in the user's environment.
- The owner's stated experiment is $5,000 with discomfort around a $1,000 loss. This app does not enforce an account-level loss limit or guarantee capital protection. Existing Kelly output is not an account-risk control.
